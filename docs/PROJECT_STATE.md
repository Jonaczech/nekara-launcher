## Current Focus

Project foundation for a custom desktop launcher dedicated to the Nekara
Minecraft server, with a player-facing frameless shell, official metadata
checks, Java runtime detection, an official file preparation flow for the base
Minecraft client, libraries, and assets, an offline launch flow, and an
offline player profile flow in place.

## Important Decisions

- The launcher is only for the Nekara server.
- The launcher must not become a general-purpose Minecraft launcher.
- There is exactly one supported game configuration: Nekara.
- The target Minecraft version is `26.1.2`.
- The Minecraft version must be defined centrally when code is introduced.
- The preferred stack is Tauri 2, React, TypeScript, Rust, Vite, and pnpm.
- React should handle UI and user interaction.
- Rust/Tauri should handle system operations, filesystem work, downloads,
  process management, Java runtime logic, authentication plumbing, and launch
  command construction.

## Verified Facts

- On 2026-06-30, `26.1.2` was found in the official Mojang/Piston version
  manifest as a `release`.
- During initial local checks, Node.js, pnpm, and npm were available.
- `pnpm typecheck` passes.
- `pnpm build` passes.
- `pnpm tauri build` passes when run from the Visual Studio developer
  environment with `~/.cargo/bin` on PATH.
- Release artifacts are produced at
  `src-tauri/target/release/bundle/nsis/Nekara Launcher_0.1.0_x64-setup.exe`
  and `src-tauri/target/release/nekara-launcher.exe`.
- The launcher UI now shows both launcher status and official metadata check
  state.
- The launcher UI now uses a custom frameless composition instead of a
  technical dashboard.
- The launcher now prepares the isolated Nekara game directory on startup.
- The launcher now detects the local Java runtime.
- The launcher now produces an initial installation plan for the isolated
  Nekara client.
- The launcher now checks whether the official version metadata JSON and client
  jar are present and valid inside the isolated game directory.
- The launcher now downloads and repairs the official version metadata JSON and
  client jar for Minecraft `26.1.2`, including SHA-1 verification for the jar.
- The launcher now downloads and repairs the official libraries, asset index,
  and asset objects required by Minecraft `26.1.2`.
- The launcher startup no longer asks the frontend to render the full raw
  `version.json`, and the UI now relies on one installation-status query
  instead of multiple duplicate metadata requests.
- The launcher now builds a first real offline Minecraft launch command from
  official metadata and starts the Minecraft process when the client is ready.
- The launcher now tracks whether Minecraft is launching, running, or exited,
  and stores a launcher-side game log path for diagnostics.
- The launcher now updates installation progress live in the UI while
  preparing the client.
- The launcher now uses an install lock file to prevent concurrent Minecraft
  prepare/repair operations against the same local data directory.
- The launcher now stores the configured Minecraft RAM limit and an optional
  custom Java executable path in launcher settings.
- The launcher now surfaces launch diagnostics, including a log excerpt,
  suggested fix, and runtime summary after failed starts.
- The launcher now prefers the configured Java executable path before falling
  back to system `PATH` resolution.
- The launcher now includes a signed GitHub Releases updater plugin and a
  release workflow that publishes Windows artifacts from tagged builds.
- ADR 0003 defines GitHub Releases as the intended first launcher self-update
  path and formalizes the no-duplicate-install strategy.
- The launcher now stores a local offline player name in launcher data.
- The launcher updater public key has been realigned with the signing key used
  by the GitHub release workflow. Existing installations that shipped with the
  old public key need one manual reinstall before future signed updates can be
  trusted automatically.
- The Fabric installation readiness calculation now includes Fabric libraries
  in the total ready library count, so a fully prepared client can leave the
  pending state.
- Brand source assets now have a dedicated `brand/` workspace with folders for
  concepts, icons, logos, and wallpapers.
- Browser preview fallback is in place so `pnpm dev` renders without Tauri
  runtime errors.
- Desktop and mobile screenshots were captured successfully from the browser
  preview.

## Notes for Future Work

  mod management.

  repository.

- Offline mode is the active player identity strategy for now; Microsoft
  account integration is deferred until the install and launch path is further
  along.
